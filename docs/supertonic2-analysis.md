# Supertonic2 서버사이드 TTS 분석

작성 목적은 **2,000명이 동시에 10분씩 리얼 면접을 사용하는 경우**에 Supertonic2를 서버사이드 TTS로 운영할 때 필요한 처리량, 메모리, 네트워크, 비용을 현실적인 가정과 공식 벤치마크를 구분하여 기록하는 것이다. 아래 수치는 견적 확정값이 아니라 **용량 계획용 추정치**이며, 실제 배포 전 부하 테스트로 보정해야 한다.

## 공식 출처와 라이선스

| 출처 | 확인 내용 |
|---|---|
| [Supertonic 공식 GitHub](https://github.com/supertone-inc/supertonic) | ONNX Runtime 기반 구현, Node.js 예제, v2 릴리스 안내, 공식 저장소 공지 |
| [Supertonic2 모델 카드](https://huggingface.co/Supertone/supertonic-2) | 한국어 지원, 66M 파라미터, CPU/WebGPU/RTX4090 벤치마크, 모델 라이선스 |
| [Supertonic2 논문](https://arxiv.org/abs/2503.23108) | 모델 구조와 기술 배경 |

공식 저장소의 샘플 코드는 MIT 라이선스이지만, **동반 모델은 OpenRAIL-M**으로 별도 취급된다. 상업 서비스에 배포하기 전에는 모델 저장소의 최신 라이선스 전문, 사용 제한, 고지 의무를 반드시 함께 검토해야 한다. 또한 공식 저장소에는 2026년 7월 23일 이후 보관 및 지원 종료 공지가 있으므로, 장기 운영에서는 Supertonic3 또는 Supertone의 관리형 API를 함께 검토해야 한다. 현재 구현은 Supertonic2를 즉시 강제 전환하지 않고, 설정된 서버 엔드포인트가 있을 때만 우선 사용하고 실패하면 기존 Edge TTS로 폴백한다.

## 공식 성능 기준

Supertonic2 모델 카드의 5-step CPU 결과는 M4 Pro에서 입력 길이 266자 기준 **약 850 characters/sec, RTF 0.018**이다. 2-step 결과는 같은 길이에서 약 1,263 characters/sec, RTF 0.012이다. 이 수치는 M4 Pro 전체 환경에서 측정된 공식 참고값이며, Manus WebDev 운영 인스턴스의 단일 vCPU 성능을 보장하지 않는다. 따라서 아래 계산은 공식 수치를 그대로 약속하지 않고, **850 characters/sec를 보수적 기준**으로 사용한다.

## 계산 가정

| 항목 | 기준값 | 의미 |
|---|---:|---|
| 사용자 수 | 2,000명 | 동시 세션 수로 가정 |
| 세션 길이 | 10분 | 총 20,000분, 333.3시간 |
| 한국어 음성 문자량 | 600자/분 | AI가 실제로 말하는 구간에 대한 계획용 가정. 문장 길이와 말하기 속도에 따라 변동 |
| 기본 TTS 비율 | 세션당 2분 | 질문·추임새·꼬리질문만 AI가 말하고 사용자는 8분 답변하는 현실적 시나리오 |
| 최악 TTS 비율 | 세션당 10분 | AI가 세션 내내 말한다고 보는 과대 추정 |
| 생성 속도 | 850자/초 | Supertonic2 공식 5-step CPU long-input 참고치 |
| 안전계수 | 3배 | 운영 오버헤드, 큐, GC, 모델 로딩, 다른 서버 작업을 위한 계획 계수 |

## 요청량과 CPU 처리량

기본 시나리오에서 TTS 문자는 `2,000명 × 2분 × 600자 = 2,400,000자`이다. 최악 시나리오에서는 `2,000명 × 10분 × 600자 = 12,000,000자`이다.

| 시나리오 | 총 TTS 문자 | 850자/초 기준 순수 합성 시간 | 3배 안전계수 적용 CPU-시간 | 10분 안에 처리하기 위한 동시 CPU 코어 방향값 |
|---|---:|---:|---:|---:|
| 기본: 사용자당 AI 발화 2분 | 2.4M자 | 약 47.1분 | 약 2.35 vCPU-시간 | 약 15 vCPU 이상 |
| 최악: 사용자당 AI 발화 10분 | 12M자 | 약 235.3분 | 약 11.76 vCPU-시간 | 약 71 vCPU 이상 |

여기서 **15 vCPU와 71 vCPU는 상시 필요 용량이 아니라, 모든 사용자가 동일한 10분 창에 몰릴 때의 버스트 처리 방향값**이다. 실제 서비스에서는 질문 생성 시점을 분산하고, 동일 질문을 캐시하며, TTS 요청을 큐로 제한하면 피크 용량을 크게 낮출 수 있다. 반대로 공식 M4 Pro 결과를 단일 vCPU에 그대로 대입할 수 없으므로, 운영 전 1·4·8·16 vCPU 인스턴스에서 p50/p95를 측정해야 한다.

짧은 면접 질문을 150자로 가정하면, 공식 850자/초 기준 순수 모델 계산은 약 0.18초이다. 다만 HTTP 왕복, 모델 세션 준비, S3 업로드, 브라우저 다운로드, 큐 대기 시간이 추가되므로 실제 사용자 체감 지연은 별도 측정 대상이다. **p95 2초 이하**를 1차 목표로 두고, 초과 시 캐시와 사전 생성 질문을 적용하는 것이 안전하다.

## 메모리와 디스크

Hugging Face의 Supertonic2 ONNX 파일 응답 크기는 다음과 같다.

| 파일 | 크기 |
|---|---:|
| duration_predictor.onnx | 1,521,526 bytes |
| text_encoder.onnx | 27,431,318 bytes |
| vector_estimator.onnx | 132,471,364 bytes |
| vocoder.onnx | 101,405,066 bytes |
| **ONNX 합계** | **262,829,274 bytes, 약 251 MiB** |

음성 스타일 JSON, 설정 파일, ONNX Runtime 세션 메모리, Node.js 힙을 포함하면 **작동 프로세스당 0.6~1.5GB RAM**을 초기 계획 범위로 잡는 것이 안전하다. 이 범위는 모델 카드의 공식 보장값이 아니라 ONNX 파일 크기와 런타임 오버헤드를 반영한 운영 추정치이다. 예를 들어 8개의 독립 worker를 실행하면 4.8~12GB RAM이 필요할 수 있으므로, worker 수를 CPU 코어 수만 보고 늘리면 안 된다. 모델 세션을 worker마다 중복 로딩하지 않는 구조 또는 인스턴스별 낮은 worker 수가 유리하다.

## 네트워크와 저장량

44.1kHz, mono, 16-bit WAV는 헤더를 제외하고 초당 약 88,200 bytes, 분당 약 5.29MB이다.

| 시나리오 | 생성 오디오 | WAV 전송량 추정 |
|---|---:|---:|
| 기본: 4,000분 | 4,000분 | 약 21.2GB |
| 최악: 20,000분 | 20,000분 | 약 105.8GB |

실제 전송량은 WAV를 압축 오디오로 변환하거나, 짧은 질문을 캐시하거나, 브라우저에서 재생 후 즉시 폐기하면 줄일 수 있다. S3에 영구 저장하기보다는 동일 문장 캐시, 짧은 TTL, 접근 권한이 있는 저장 URL을 사용해야 한다. 네트워크·S3 비용은 현재 연결된 호스팅과 리전의 요금표가 필요하므로 아래 비용에 고정값으로 포함하지 않는다.

## 운영비 산정

Supertonic2 자체에는 문자당 API 비용이 없다. 따라서 비용은 **CPU/RAM 인스턴스 시간 + 모델 저장공간 + 오디오 전송/S3 + 모니터링**으로 구성된다.

```text
월 운영비 = (vCPU 시간 × vCPU 단가)
          + (GB-RAM 시간 × RAM 단가)
          + (저장 GB × 저장 단가)
          + (전송 GB × 전송 단가)
          + 모니터링/예약 인스턴스 비용
```

이 프로젝트의 Manus 호스팅 단가가 문서에 노출되어 있지 않으므로 원화 금액을 임의로 확정하지 않는다. 위 계산으로 확인할 수 있는 것은 다음과 같다.

| 항목 | 결론 |
|---|---|
| TTS API 문자 과금 | 0원에 가까움. 외부 TTS API를 호출하지 않는다는 전제 |
| 서버 CPU | 기본 버스트는 약 15 vCPU 방향값, 최악은 약 71 vCPU 방향값. 실측 없이는 예약 확정 금지 |
| 서버 RAM | 8 worker 기준 대략 4.8~12GB 계획 범위. 세션 중복 로딩 여부에 따라 크게 변동 |
| 오디오 전송 | 기본 약 21.2GB, 최악 약 105.8GB/동일 이벤트. 압축·캐시로 감소 가능 |
| 가장 현실적인 절감책 | 사전 생성 질문 캐시, 같은 문장 캐시, 요청 큐, 5-step 또는 8-step 품질, 짧은 TTL |

## 권장 운영 구조

1. 리얼 면접 질문을 생성할 때 문장을 정규화하고, `voice + steps + speed + text`를 캐시 키로 사용한다.
2. TTS 요청에 길이 제한, 20초 timeout, 동시성 큐를 둔다.
3. `SUPERTONIC2_TTS_URL`이 설정된 환경에서만 Supertonic2 HTTP 서버를 사용한다.
4. Supertonic2 응답 오류, 모델 서버 중단, WAV 형식 오류가 발생하면 Edge TTS로 폴백한다.
5. 모바일 브라우저 자동재생이 거부되면 녹음을 바로 시작하지 않고, **질문 다시 듣기/음성 재시도/답변 시작** 버튼을 표시한다.
6. 실제 전환 전 50·100·250 동시 요청 부하 테스트와 한국어 회사명·직무명·숫자 발음 A/B 테스트를 수행한다.

## 현재 코드 반영 범위

- `server/_core/supertonicTTS.ts`: 공식 `/v1/tts` HTTP 계약을 호출하고 WAV를 S3에 저장하는 어댑터, 짧은 TTL 메모리 캐시, timeout, 음성 매핑을 제공한다.
- `server/routers.ts`: `SUPERTONIC2_TTS_URL`이 있으면 Supertonic2를 우선 사용하고, 실패하면 기존 Edge TTS를 사용한다.
- `server/_core/edgeTTS.ts`: 질문 텍스트를 Python 코드에 직접 삽입하지 않고 argv로 전달하여 따옴표·개행이 포함된 문장의 실패 가능성을 줄였다.
- `client/src/pages/RealInterview.tsx`: 자동재생 실패 시 화면을 유지하고, 질문 다시 듣기·음성 재시도·답변 시작·설정으로 돌아가기·답변 제출 후 다음 질문 버튼을 제공한다.

## 아직 운영 전환하지 않은 항목

현재 프로젝트에는 `SUPERTONIC2_TTS_URL`을 설정하지 않았으므로 기존 환경은 Edge TTS 폴백으로 동작한다. 따라서 Supertonic2 모델을 이 프로젝트 이미지에 무조건 포함하거나, 외부 유료 인프라를 자동 생성하지 않았다. 실제 Supertonic2 서버를 운영하려면 모델 서버를 별도로 실행하고, 사용자 승인 후 해당 URL을 환경 설정에 연결해야 한다.


## Azure Speech 한국어 음성 확인

Microsoft 공식 언어 지원 문서(https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support?tabs=stt)는 `ko-KR`을 Azure Speech 지원 로케일로 기재한다. 실제 voice ID와 성별·스타일은 서버의 `edgeTTS.ts` 매핑을 기준으로 고정하고, 브라우저 `speechSynthesis`는 보조 폴백으로만 사용한다. 특정 브라우저가 동일한 기본 음성을 반환하는 문제를 피하기 위해 서버 생성 음성의 provider와 voice 정보를 응답·화면에 표시하는 것을 원칙으로 한다.
