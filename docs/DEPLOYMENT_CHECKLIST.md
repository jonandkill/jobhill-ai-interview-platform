# 운영 배포 체크리스트

이 문서는 JOB HILL AI 모의면접 플랫폼을 스테이징에서 검증하고 운영으로 승격하기 위한 필수 확인 목록입니다. 체크되지 않은 항목이 있으면 해당 릴리스는 보류합니다.

## 1. 자격 증명과 저장소

- [ ] 과거 프로젝트 파일에 포함되었던 DB, JWT, AWS/S3, AI, Stripe, Toss, 키움페이 자격 증명을 모두 폐기·재발급했다.
- [ ] 폐기 전 키의 사용·접근 로그를 검토하고 의심 활동을 별도로 기록했다.
- [ ] `.env`, `.env.*`, `.manus/`, `.project-config.json`, 운영 로그, DB 덤프와 사용자 업로드가 Git 이력에 없는지 확인했다.
- [ ] GitHub Secret에는 운영 비밀을 넣지 않고 배포 플랫폼의 환경별 Secret 저장소를 사용한다. 배포 자동화에 GitHub Secret이 꼭 필요하다면 최소 권한·환경 승인·회전 정책을 적용한다.
- [ ] `VITE_` 접두사에는 공개 가능한 클라이언트 값만 들어 있다.
- [ ] 영수증과 공개 약관·개인정보 고지용 `BUSINESS_*`, `VITE_BUSINESS_*`, `VITE_SUPPORT_*` 값을 실제 사업자 정보로 설정했다.

## 2. 릴리스 품질 게이트

- [ ] pull request에서 GitHub Actions CI가 성공했다.
- [ ] `pnpm install --frozen-lockfile`로 잠금 파일과 의존성이 일치한다.
- [ ] `pnpm check`, `pnpm test:ci`, `pnpm build`가 깨끗한 Node.js 22 환경에서 성공한다.
- [ ] 스테이징에서 DB·OAuth·결제·STT/TTS가 필요한 전체 통합 테스트를 별도로 통과했다.
- [ ] 릴리스 커밋 SHA, 빌드 일시, 마이그레이션 버전과 배포자를 기록했다.

## 3. 데이터베이스

- [ ] 운영 DB의 암호화 백업을 만들고 실제 복구 절차를 시험했다.
- [ ] 현재 운영 스키마와 `drizzle/` 마이그레이션 차이를 스테이징 복제본에서 먼저 확인했다.
- [ ] 중복 번호를 포함한 기존 마이그레이션 파일 순서를 검토하고, 운영 DB에 적용된 이력과 대조했다.
- [ ] 마이그레이션은 웹 프로세스 시작과 분리된 단일 작업으로 한 번만 실행한다.
- [ ] 실패 시 되돌릴 DB 절차와 이전 애플리케이션 릴리스의 스키마 호환 범위를 확인했다.
- [ ] 결제 pending→완료, 중복 승인 재시도, 취소·환불, 크레딧 원복의 원자성을 스테이징에서 검증했다.

## 4. 런타임과 자산

- [ ] Node.js 22.x와 pnpm 10.x를 사용한다.
- [ ] `server/assets/fonts/NotoSansCJK-Regular.ttc`와 `NotoSansCJK-Bold.ttc` 또는 동일한 시스템 글꼴을 제공하고 한글 PDF를 눈으로 확인했다.
- [ ] `services/qwen3-tts`의 Qwen3-TTS 모델·코드 revision을 고정하고, 모델을 추론 컨테이너에 읽기 전용으로 마운트했다.
- [ ] Qwen3-TTS 서비스 토큰을 32자 이상으로 생성해 앱과 사이드카의 Secret 저장소에만 등록했다.
- [ ] 서버 측 외부 Edge TTS가 비활성화되어 질문이 제3자 음성 서비스로 전송되지 않는지 확인했다.
- [ ] AI·음성·스토리지 공급자에 필요한 outbound HTTPS만 방화벽에서 허용했다.
- [ ] 플랫폼의 영구 저장소와 임시 파일 정책을 구분하고 `/tmp`가 주기적으로 정리되는지 확인했다.

## 5. 운영 환경변수

- [ ] `DATABASE_URL`, 32자 이상의 `JWT_SECRET`, `VITE_APP_ID`, `OAUTH_SERVER_URL`, `OAUTH_PORTAL_URL`이 환경별로 설정됐다.
- [ ] `APP_BASE_URL`이 최종 공개 HTTPS 원점과 정확히 일치하며 경로나 후행 슬래시를 넣지 않았다.
- [ ] AI 기능을 사용할 경우 `BUILT_IN_FORGE_API_URL`과 서버 전용 `BUILT_IN_FORGE_API_KEY`를 설정했다.
- [ ] 음성 질문을 사용할 경우 `QWEN3_TTS_URL`, `QWEN3_TTS_TOKEN`을 설정하고 `/healthz`와 실제 한국어 합성을 통과했다.
- [ ] Qwen 폴백을 사용할 경우에만 별도 내부 `SUPERTONIC3_TTS_URL`과 서비스 토큰을 설정했다.
- [ ] Toss를 사용할 경우 공개 클라이언트 키와 서버 시크릿 키의 test/live 환경이 일치한다.
- [ ] 스케줄 API를 사용할 경우 예측 불가능한 32자 이상의 `SCHEDULER_SECRET`을 설정했다.
- [ ] 사용하지 않는 레거시 Stripe·키움페이 값은 비워 두고 관련 경로가 외부에 노출되지 않는지 확인했다.

## 6. 네트워크·인증·결제

- [ ] TLS 인증서, HTTP→HTTPS 리디렉션, HSTS와 보안 헤더를 실제 도메인에서 확인했다.
- [ ] 프록시가 원래 프로토콜과 호스트를 올바르게 전달하고 Express의 단일 `trust proxy` 설정과 일치한다.
- [ ] OAuth 공급자에 `https://<domain>/api/oauth/callback`을 정확히 등록했다.
- [ ] 정상 로그인, state 변조, state 재사용, 만료, 로그아웃과 외부 URL 리디렉션 거부를 시험했다.
- [ ] Toss 테스트 상점에서 준비→승인→중복 콜백→취소·환불을 검증한 뒤에만 live 키로 전환한다.
- [ ] tRPC `system.health`가 200과 `{ ok: true }`를 반환하며 DB 장애와 무관한 liveness 용도임을 모니터링 시스템에 명시했다.

## 7. 카메라·마이크와 접근성

- [ ] Chrome, Edge, Safari와 iOS/Android 실제 장치에서 카메라·마이크 허용, 거절, 재시도, 장치 없음·점유를 시험했다.
- [ ] 페이지 이동, 면접 종료, 오류와 백그라운드 전환 후 카메라·마이크 사용 표시가 꺼지는지 확인했다.
- [ ] 전화 수신·화면 잠금 후 복귀와 장치 방향 전환에서 답변 입력이 보존된다.
- [ ] 390px 모바일 폭, 200% 확대, 키보드 탐색, 스크린리더 이름, 색 대비와 44px 터치 대상을 확인했다.
- [ ] 카메라가 표정·감정·성격·합격 가능성 추론에 사용되지 않는다는 안내가 권한 요청 전에 보인다.

## 8. AI와 개인정보

- [ ] AI 피드백이 답변 원문 근거와 고정 루브릭을 사용하고 답변에 없는 경력·성과·수치를 생성하지 않는지 표본 검수했다.
- [ ] AI 실패 시 가짜 점수나 합격 확률을 만들지 않고 오류와 크레딧 원복이 정상 동작한다.
- [ ] 음성 전사·AI·스토리지 공급자, 전송 항목, 처리 국가, 보존 기간, 삭제 절차와 위탁 계약을 확인했다.
- [ ] TTS 질문과 생성 WAV가 로그, DB, S3, CDN, 임시 파일 또는 애플리케이션 캐시에 남지 않는지 확인했다.
- [ ] Qwen3-TTS의 음성 복제·사용자 음성 업로드 경로가 비활성화되어 있는지 확인했다.
- [ ] 개인정보처리방침과 서비스 화면의 설명이 실제 코드·공급자 설정과 일치한다.
- [ ] 사용자 탈퇴·삭제 요청 시 계정, 면접, 음성·전사, 공유 링크와 백업의 처리 절차를 시험했다.
- [ ] 공유 링크는 비공개 기본값, 충분히 긴 난수, 폐기 기능과 접근 로그를 갖는다.

## 9. 확장성·관측성

- [ ] 단일 인스턴스에서는 메모리 rate limit의 재시작 초기화와 한계를 운영 문서에 기록했다.
- [ ] 수평 확장 전 rate limit을 Redis 등 공유 저장소로 교체했다.
- [ ] 내장 스케줄러는 웹 인스턴스마다 실행되므로, 수평 확장 전 전용 worker 또는 분산 잠금으로 단일 실행을 보장했다.
- [ ] 구조화 로그에서 세션 쿠키, Authorization, 결제키, 음성·답변 원문과 개인정보를 마스킹했다.
- [ ] 오류율, p95 응답시간, AI·STT/TTS 지연과 비용, DB 연결, 결제 승인 실패, 권한 거절률을 모니터링한다.
- [ ] 오류 추적과 비용 알림의 담당자·응답 기준·야간 연락 절차를 정했다.

## 10. 점진 배포와 복구

- [ ] 스테이징과 운영의 DB·OAuth·결제·스토리지 자격 증명이 완전히 분리됐다.
- [ ] 내부 계정 또는 소수 사용자에게 먼저 배포하고 첫 면접 완료율, 권한 거절률, AI 실패율, 재연습 전환율을 확인했다.
- [ ] 이전 애플리케이션 산출물을 보존하고 무중단 또는 짧은 유지보수 창의 rollback 명령을 검증했다.
- [ ] rollback 시 이미 적용된 DB 마이그레이션·신규 결제 상태를 어떻게 처리할지 결정했다.
- [ ] 운영 승격 후 OAuth, 카메라, 텍스트·음성 면접, 결과 조회, PDF, 결제의 핵심 smoke test를 다시 수행했다.
- [ ] 배포 후 24시간 집중 모니터링 담당자를 지정했다.

## 11. Qwen3-TTS 음질 승인

- [ ] 한국인 평가자 5명 이상이 30개 이상의 실제 면접 질문을 블라인드 평가했다.
- [ ] 자연스러움·질문 억양 평균 4.0/5 이상, 발음 오류율 2% 이하를 충족했다.
- [ ] 숫자, 회사명, KPI/OEE, 생산·품질·안전 용어와 영문 약어를 표본 검증했다.
- [ ] 100회 합성에서 반복·누락이 없고 250자 warm p95가 2초 이하인지 확인했다.
- [ ] iPhone Safari와 Android Chrome에서 최초 재생, 중단, 다시 듣기를 통과했다.
- [ ] 자세한 절차는 `docs/QWEN3_TTS_DEPLOYMENT.md`와 일치한다.
